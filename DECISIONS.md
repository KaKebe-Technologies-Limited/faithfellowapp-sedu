# FaithFellows — Technical Decisions Log

Decisions made while building FaithFellows, with the reasoning behind each. Newest sprint last.

## Sprint 1 — Foundation

| # | Decision | Why |
|---|----------|-----|
| 1 | **Laravel 12 instead of Laravel 11.** | All Laravel 11 releases are now blocked by Composer because of unpatched security advisories (Laravel 11 reached end of life in early 2026). Laravel 12 has the same application structure (`bootstrap/app.php`, slim skeleton), runs on PHP 8.2 and receives security fixes until Feb 2027. Upgrading to Laravel 13 needs PHP 8.3+. |
| 2 | **MariaDB 10.4 (XAMPP) locally, MySQL 8 in production.** | XAMPP ships MariaDB. All migrations avoid MySQL-8-only features (no functional indexes or CHECK reliance), so the schema runs on both. Tests run against a real MySQL database (`faithfellows_test`), not SQLite, so enums and JSON behave as they will in production. |
| 3 | **Bootstrap 5.3 compiled from SCSS** (`resources/scss/app.scss`) with brand variables, plus `resources/css/faithfellows.css` for tokens and `.ff-*` components. | Compiling from SCSS makes Bootstrap's own components (forms, pagination, focus rings) use Viva Magenta without overriding them in CSS. No Tailwind (removed from the Breeze scaffold). |
| 4 | **Space Grotesk is self-hosted** via `@fontsource/space-grotesk` (woff2) instead of the Google Fonts CDN. | Same font as the brand guide, served from our own origin: no third-party request, cached by the service worker, works offline and on slow networks. The brand-supplied TTFs (`resources/fonts`) are used by DomPDF for receipts. |
| 5 | **Breeze Blade stack, Tailwind views replaced.** | We keep Breeze's auth controllers and requests (battle-tested), but every view is rewritten in Bootstrap and Blade components (`x-ff.*`, `x-layouts.*`). |
| 6 | **Logo rebuilt as a lightweight inline SVG** (`x-logo`, `x-logo-mark`, `public/favicon.svg`). | The brand guide's Illustrator export is 125 KB. The mark was traced from the guide's geometry into a 100×100 viewBox (≈400 bytes) that inherits `currentColor` for white or magenta variants. PNG icons and the OG image are generated by `scripts/make-brand-images.php`. |
| 7 | **Heavy JS libraries are lazy-loaded** (Chart.js, Quill, hls.js, Leaflet). | Keeps the first page load small on 3G. Each loads only on pages that use `data-ff-chart`, `data-ff-editor`, a live player or `data-ff-map`. |
| 8 | **Platform roles use Spatie** (`super_admin`, `church_admin`, `staff`, `member`). **Church sub-roles use our own `church_roles` table** (Sprint 2) with a permission catalog in `config/faithfellows.php`. | A user can be Finance in one church and only a member in another. Spatie's global roles answer "what kind of user is this?"; church roles answer "what can this user do in this church?". |
| 9 | **Super admins bypass policies via `Gate::before`.** | Support staff need full access. Every action is still written to `audit_logs`. |
| 10 | **`notifications` keeps Laravel's UUID primary key** and adds `church_id` and `category` columns (via `TenantDatabaseChannel`). | Laravel's database notification channel requires UUIDs. The extra columns let the notification center filter by church and category without JSON queries. |
| 11 | **`audit_logs.church_id` is nullable.** | Platform-level actions (approving a church, changing gateway keys) don't belong to a church. Church-level actions always set it. |
| 12 | **Email-OTP two-factor authentication + magic-link login** were added in Sprint 1, not deferred to Phase 2. | Both are small, dependency-free and useful on shared phones. TOTP apps can be added later. |
| 13 | **Account deletion anonymises the user** (soft delete + scrubbed PII) instead of hard-deleting. | Donation records must survive for church accounting. The person's identity is removed. |
| 14 | **Timezone `Africa/Kampala`** is the app default. Users have their own timezone for quiet hours. | Service times, reminders and reports are local to Uganda. |
| 15 | **Low-bandwidth "lite" mode** is a cookie (`ff_lite`) or a user preference. It adds the `.ff-lite` class to `<body>`. | Pure CSS degradation: decorative media is hidden, animation is off and live players default to audio-only. Works for guests too. |
| 16 | **Rich text is sanitised on output** with `ff_safe_html()` (allow-list). | Quill produces HTML. Blade escapes everything else, so this helper is the only place raw HTML is rendered. |
| 17 | **Local dev runs on `php artisan serve` at http://127.0.0.1:8000.** Church subdomains use `*.localhost` (Chrome resolves these to 127.0.0.1). | XAMPP's Apache would need vhost changes for subdomains. Production uses Nginx with a wildcard `*.faithfellows.app` server block. |

## Sprint 2 — Churches & Roles

| # | Decision | Why |
|---|----------|-----|
| 18 | **Tenant isolation has three layers:** (1) `church.staff` middleware binds the current church, (2) `scopeBindings()` on `/church/{church}/admin/*` resolves every child model through the church's relationship (another church's record returns 404), and (3) policies and `church.can:<permission>` middleware check `User::canInChurch()`. | Defence in depth: a forgotten `where church_id` in one place can't leak another church's data. Tests cover each layer. |
| 19 | **Church sub-roles store permissions as a JSON array** on `church_roles`, validated against the catalog in `config/faithfellows.php`. A staff row has either `is_admin = true` (all permissions) or one `church_role_id`. | Simple to reason about, easy to render as a checkbox matrix, and needs no extra pivot tables. Five presets (Editor, Finance, Media, Events, Moderator) are created when a church is approved. |
| 20 | **Church applications require a signed-in, verified account.** The applicant becomes the first church admin. Guests are sent to register and then returned to the form. | One email, one account: the applicant needs an account to manage the church anyway, and it keeps spam applications down. |
| 21 | **Kakebe can onboard churches directly** (super admin → "Onboard a church"). Unknown admin emails get an account plus a password-setup link, which is a standard reset token. | This is the "invited by Kakebe" path from the spec, with no separate invitation table needed. |
| 22 | **Subdomains use `Route::domain('{subdomain}.'.FF_ROOT_DOMAIN)`.** Verified custom domains are resolved by `ResolveCustomDomain` middleware. Locally, `FF_ROOT_DOMAIN=localhost` makes `grace-lira.localhost:8000` work in Chrome without editing the hosts file. | Production: a wildcard DNS record `*.faithfellows.app` plus one Nginx server block. Links on church sites use `ff_platform_route()` so sign-in and giving happen on the main domain (one session cookie). |
| 23 | **The website builder stores an ordered list of `{type, enabled}` blocks** on `churches.website_blocks`. Each block is a Blade partial in `church-site/blocks/`. | Drag-and-drop ordering and toggles need no page-builder dependency. New block types appear automatically (disabled) for existing churches. |
| 24 | **Super admins impersonate via a session flag** (`impersonator_id`). A banner is shown, and start/stop plus every action taken are attributed in `audit_logs.impersonator_id`. | This meets the support requirement with a full audit trail. Super admins can't impersonate other super admins. |
| 25 | **`media.church_id`** is set automatically by `App\Models\Media` from the owning model. | Per-church storage quotas and the "storage per church" super admin analytics need it. |
| 26 | **Lazy-loading violations are logged, not thrown**, in development. | Blade views must not query (spec rule). Violations surface in `storage/logs` without breaking pages for testers. |

## Sprint 3 — Subscriptions & Feed

| # | Decision | Why |
|---|----------|-----|
| 27 | **Unsubscribing sets `status = left`** instead of deleting the row. Re-subscribing re-activates the same row. | Keeps the first-subscribed date and the follow-up stage, so growth and retention analytics stay accurate. `blocked` members can't re-subscribe. |
| 28 | **`subscriptions.stage` (visitor → new member → member → worker → leader)** is the follow-up workflow, edited inline in the member manager. | This covers M3 ("visitor → member → leader") without a separate pipeline table. |
| 29 | **Notification preferences resolve church row → global row → defaults** (`PreferenceResolver`). An empty channel list means "off". Users can only save preferences for churches they follow. | Users get fine-grained control (per church × category × channel) with sensible defaults and no rows written until something changes. |
| 30 | **The feed merges per-source queries** (posts now; sermons, events, campaigns, live and announcements in later sprints) and pages with a `before` timestamp cursor. | Each module adds a small source closure in `FeedService`. A timestamp cursor doesn't skip or repeat items when new posts arrive. |
| 31 | **Members-only content** is visible to active subscribers and church staff (`User::memberChurchIds()`). | One rule shared by feed, church pages, directory and later the prayer wall. |
| 32 | **The member directory is opt-in twice:** global `directory_opt_in` and active membership of that church. Only members of the church can browse it. | Privacy by default for congregations. |
| 33 | **Member CSV exports include an email only when that member consented** (`share_email`). All CSV cells are guarded against formula injection. | Implements the consent requirement (U5). |
| 34 | **`/churches` is the shared directory** (public layout for guests, member layout when signed in). "My subscriptions" moved to `/my-churches`. | The spec listed `/churches` for both the public directory and member subscriptions, so one URL had to move. |
| 35 | **Guests who click Subscribe** go to `/churches/{slug}/join` (auth-protected). After sign-up Laravel's intended-URL brings them back to confirm. | Avoids a state-changing GET while keeping the "prompted to sign up" visitor flow. |

## Sprint 4 — Content Management

| # | Decision | Why |
|---|----------|-----|
| 36 | **Sermon media can be uploaded or linked.** Audio/video files go to Media Library; `audio_url` and `video_url` accept external hosting such as YouTube or Facebook (rendered as privacy-friendly `youtube-nocookie` embeds). | Churches often already stream to YouTube. Linking avoids storage cost, while uploads keep data-light MP3s on our CDN for offline saving. |
| 37 | **Publishing states: draft → scheduled → published.** `Publishable::resolvePublishing()` marks future dates as `scheduled`. `ff:publish-scheduled` runs every minute and notifies subscribers once (`notified_at`). | Scheduled posts are a spec requirement. `notified_at` makes notifications idempotent across edits and scheduler runs. |
| 38 | **`ChurchNotification` base class + `NotificationService`.** Subclasses only describe the message; channels are picked per recipient from preferences. The fan-out runs in the queued `NotifyChurchMembers` job and is delivered with `sendNow` in chunks of 500. | Large churches never block a request, and the queue doesn't explode into one job per user × channel. Sprint 8 adds SMS, WhatsApp, push, quiet hours and digest in this same service. |
| 39 | **Announcement audiences:** public, members, staff, branch and small group, enforced by both the feed query and `AnnouncementPolicy`. Admins can add email, SMS or WhatsApp delivery per announcement (`forceChannels`). | Covers "target by group" and multi-channel announcements. |
| 40 | **Rich text uses Quill** (lazy-loaded) and is sanitised with `ff_safe_html()` both on save and on output. | Defence in depth against stored XSS. |
| 41 | **Reading plans store their schedule as JSON entries** (one per day). Templates (Bible in a Year, NT in 90 days, Gospels in 30, Proverbs) are generated from a canonical chapter list. Progress tracks completed days, current and longest streak. | No per-day table is needed, and plans import in one click. "Day 47 of 365" is the next unread day. |
| 42 | **Offline sermons use the browser Cache API** through the service worker ("Save offline") and are listed on `/offline`. | True offline listening without a native app. Downloads are also available as files. |
| 43 | **Sermon AI is a Phase 2 stub:** `TranscriptionService` plus the `TranscribeSermon` job. Manual transcripts work today and make sermons searchable by spoken words. | The data model (`sermon_transcripts` with summary, key verses and questions) is ready, so a provider can be plugged in without migrations. |
| 44 | **Search uses SQL `LIKE`** across titles, preachers, scripture, bodies and transcripts (`SearchService`). | Good enough for an MVP on shared hosting. It can move to MySQL FULLTEXT or Meilisearch behind the same service. |
| 45 | **Storage quotas are checked at validation time** (`WithinStorageQuota`) using `media.church_id` sums. The limit comes from the church's plan (Sprint 6), otherwise `FF_DEFAULT_STORAGE_MB`. | Enforces "usage limits: storage" before files hit disk. |
| 46 | **Engagement analytics** are stored per event in `content_views` (view, listen with seconds, watch, download). Counter columns on sermons are kept for fast lists. Views are de-duplicated per session. | Powers "views, listens, watch time" analytics in Sprint 8 without double counting refreshes. |

## Sprint 5 — Events & Live Streams

| # | Decision | Why |
|---|----------|-----|
| 47 | **Live streaming supports four sources:** FaithFellows RTMP (nginx-rtmp or Cloudflare Stream → HLS), YouTube, Facebook or any HLS URL. | Many Ugandan churches already stream to YouTube or Facebook. RTMP gives them their own player with an **audio-only rendition** (`{key}_audio.m3u8`) for data-light listening. |
| 48 | **Going live is automatic for RTMP.** The nginx-rtmp `on_publish` / `on_publish_done` callbacks hit `/webhooks/rtmp/*`, and unknown keys get 403. Stream keys are **encrypted at rest**, with a SHA-256 hash for lookup. | Pressing "Start" in OBS or Larix is all a media volunteer has to do. A leaked database dump doesn't leak broadcast rights. |
| 49 | **Viewer counts come from a 30-second heartbeat** into `live_stream_viewers` (75-second window), with peak tracking. **Live chat uses 5-second polling.** | Works on shared hosting and flaky 3G without WebSockets. Reverb broadcasting can replace polling later behind the same endpoints. |
| 50 | **Auto-archive:** ending a stream records the recording URL. "Archive as sermon" creates a published sermon (marked already-notified, since members were alerted when the service went live). | Covers "auto-archive recording as sermon after service" without double notifications. |
| 51 | **RSVP capacity is enforced inside a DB transaction with `lockForUpdate`** on the event. Paid tickets create `pending_payment` RSVPs that the giving flow confirms (Sprint 6). | Prevents overbooking the last seats under concurrent requests. |
| 52 | **QR check-in:** each RSVP has a unique 10-character code. The ticket QR encodes the staff check-in URL, so any staff phone camera can scan it (no scanner app). Manual code entry is the fallback. | No extra hardware or JavaScript QR library needed at the door. |
| 53 | **Reminders** run via `ff:event-reminders` every 5 minutes (24h and 1h windows, idempotent via `reminder_*_sent_at`). | Meets K7 with exactly-once delivery. |
| 54 | Seat selection (K4, optional) is modelled with an `event_rsvps.seat` column but has no seat-map UI yet. | Rarely needed by pilot churches. The column avoids a later migration. |

## Sprint 6 — Giving & Campaigns

| # | Decision | Why |
|---|----------|-----|
| 55 | **`PaymentService::driver($method)`** returns a `PaymentDriver` (MTN MoMo, Airtel Money, Iotec, Stripe, Manual). Drivers take a `Payable` (donations, ticket purchases, subscription invoices) instead of only a `Donation`. `webhook()` returns `?PaymentResult` rather than `void`. | One payment pipeline for gifts, tickets and church billing. Returning the parsed result keeps drivers free of business logic, and `DonationService` decides what to do with it. |
| 56 | **Sandbox mode** (`PAYMENTS_SANDBOX=true`, or no gateway credentials) uses `SandboxDriver`. Mobile money "approves" after about 4 seconds; numbers ending `0000` are declined and `1111` never respond. Card payments go through a local fake checkout. | The whole giving flow (receipts, campaign progress, milestones, tickets) can be demoed and tested without real money or gateway accounts. |
| 57 | **Mobile-money callbacks are never trusted.** The webhook only identifies the transaction, and the status is re-fetched from the gateway API (`DonationService::sync`). Stripe events are verified by HMAC signature with a 5-minute tolerance. | MTN and Airtel callbacks aren't signed by default. Re-verifying prevents forged "payment successful" posts (covered by a test). |
| 58 | **Idempotency:** `markSucceeded()` locks the donation row, refuses a `provider_ref` that already completed another donation (it's also a unique index), and fires `DonationSucceeded` exactly once. | Webhook retries, duplicate callbacks and the status-polling page can race safely. |
| 59 | **`ff:payments-reconcile` runs every 5 minutes** to re-check pending payments whose callbacks never arrived, and expires them after 24 hours. | Callbacks get lost on flaky networks, and givers shouldn't be left "pending" forever. |
| 60 | **Side effects are listeners on `DonationSucceeded`:** receipt (PDF + email + in-app + optional SMS), campaign recalculation (milestones and goal celebration), finance alert, pledge balance, ticket confirmation. Pledges and tickets are handled synchronously; the rest are queued. | Keeps the money path small and testable. The event also broadcasts to `church.{id}.finance` for real-time dashboards. |
| 61 | **Receipts are numbered `R{church}-{yy}-{donationId}`** and rendered by DomPDF with embedded (data-URI) logos, cached on the private `local` disk. | Unique without counters (no race), and no remote fetches inside PDF rendering. |
| 62 | **Campaign totals are denormalised** (`raised_amount`, `givers_count`, team totals) and recomputed from confirmed gifts after every gift or refund. Milestones (25/50/75/100%) are rows with `reached_at`, so each celebration fires once. | Fast campaign pages with exact numbers; refunds lower progress correctly. |
| 63 | **Leaderboards are opt-in per gift** (`show_on_leaderboard` and not anonymous). | Generosity is often private in Ugandan churches. |
| 64 | **Diaspora mode** reads Cloudflare's `CF-IPCountry` (falling back to the profile country) and shows card payments first outside Uganda. | Matches H12 without a GeoIP database. |
| 65 | **Recurring card gifts send a reminder with a pay link** instead of charging off-session. Recurring mobile money sends a fresh prompt on the due date. | Mobile money can't be charged without the giver's PIN, and storing card mandates needs extra Stripe setup (SCA). Both give a predictable experience. |
| 66 | **Reconciliation:** bank statement CSV import auto-matches lines by `FF…` reference, or by a unique pending bank transfer of the same amount within ±3 days. Everything else is matched by hand. | Treasurers already download CSV statements, and nothing is auto-matched ambiguously. |
| 67 | **Payouts** group settled online gifts into a payout record that finance marks paid (with bank reference). Failing a payout releases its gifts. | Tracks "payout status to church account" (G8) whether settlement is manual or automated later. |
| 68 | **Church billing (Section O) lives here** because it uses the same payment drivers: plans, 12-month trial, monthly invoices issued 7 days ahead, `ff:billing` daily for overdue → reminders → suspension after `FF_GRACE_DAYS`. Paying reactivates instantly. | One payments stack for the whole platform. |
| 69 | **USSD giving** (`/webhooks/ussd`, Africa's Talking) uses church numeric codes and starts a mobile-money prompt through the church's first enabled MoMo channel. | Works on feature phones with no data. |

## Sprint 7 — Community & Engagement

| # | Decision | Why |
|---|----------|-----|
| 70 | **Prayer visibility has three levels:** `public` (anyone, including the church website), `church` (subscribers and staff), `pastor` (author plus staff with `prayer.moderate` or `care.manage`). One `PrayerRequest::visibleTo()` scope serves the wall, feed and church page, and the policy repeats the same rules for single requests. | Many requests are private family matters, so pastor-only requests never reach the feed, the church page or a prayer chain. |
| 71 | **"I prayed" is a unique `prayer_interactions` row** (`prayed`) with a denormalised `prayed_count`. The toggle is AJAX (`prayButton` Alpine component). When a request is marked answered, everyone who prayed is told. | Gives a cheap count on every card, and closes the loop: people learn how their prayers were answered. |
| 72 | **Prayer chains** ask one random church member at a time (a `chain` interaction), up to 12 links. When that person prays, the next one is asked. Pastor-only requests never start a chain. | A gentle relay that keeps a request moving without notifying the whole church at once. |
| 73 | **Testimonies are moderated** (`pending` → `approved`/`rejected`, `community.moderate`) and can link back to the answered prayer. | Testimonies are public-facing, so churches review them first. |
| 74 | **Reactions and comments are polymorphic** (`HasEngagement` trait plus one `partials.engagement-bar`) on posts, sermons, testimonies, campaign updates and prayers. Access follows the parent: members-only content needs membership, and prayers defer to the prayer policy. Comment bodies are stored as plain text (tags stripped). | One moderation queue (`church-admin.comments`) and one UI component for every content type. |
| 75 | **Group leaders aren't church staff.** Leader tools (approve joins, take attendance, group announcements) live on the member-facing group page and are authorised by `SmallGroupPolicy::lead` (leader, assistant, or staff with `groups.manage`). The admin area only handles group CRUD. | Cell leaders are ordinary members and shouldn't need the church admin panel. |
| 76 | **Group announcements reuse the Sprint 4 `audience = group` announcements**, notifying only active group members. Cell offerings are recorded per meeting, and online cell giving tags `donations.small_group_id` via `give.create?group=`. | No parallel messaging or giving system. |
| 77 | **Service check-in:** the printable QR encodes a **signed URL that expires at midnight**. The check-in form posts back to the same signed URL (signature checked server-side), and members without the QR can use **geofence** check-in (haversine distance, default radius 250 m, `settings.checkin_radius`). One record per member per day. | A screenshot of the QR is useless the next day, and the location fallback works for latecomers. |
| 78 | **Volunteer rota:** assigning a volunteer notifies them, they confirm or decline from `/serving`, declines show up as "need cover" for admins, and `ff:rota-reminders` (18:00 daily) reminds tomorrow's volunteers once (`reminded_at`). | Replaces the WhatsApp-group rota with confirmations and reminders. |
| 79 | **Pastoral data is encrypted at rest** (Laravel `encrypted` cast): pastoral notes, welfare notes, home-visit notes, counseling topic and counselor notes. Notes are private to their author by default. The counseling topic is `$hidden` from serialisation. | Section care data is confidential (spec), and a database leak or a stray `toArray()` must not expose it. |
| 80 | **Super admins can't read counseling notes.** `Gate::before` grants super admins everything except the `viewNotes` ability, and `CounselingAppointmentPolicy::before` denies it explicitly. | Platform staff support churches but have no pastoral relationship with members. |
| 81 | **Care dashboard data is computed, not stored:** birthdays and anniversaries in the next 14 days, visitors and new members from the last 60 days needing follow-up, and regular attenders absent 3+ weeks ("we miss you"). The Monday `ff:care-digest` sends the counts to the pastoral team. | Always current, with no sync jobs. |
| 82 | **The home feed adds `prayer` and `testimony` items**, and engagement relations are eager-loaded per source, so the feed stays a fixed number of queries. | Community activity sits next to sermons and announcements without N+1 queries. |
| 83 | **Sprint 7 styles live in `resources/css/community.css`** (imported from `app.js`) and don't touch `faithfellows.css`. | `faithfellows.css` has uncommitted redesign work in progress, so Sprint 7 doesn't touch it. |

## Sprint 8 — Notifications & Analytics

| # | Decision | Why |
|---|----------|-----|
| 84 | **Five delivery channels behind one `ChurchNotification`:** in-app (database), email, Web Push (VAPID via `minishlink/web-push`), SMS and WhatsApp (Africa's Talking), plus optional real-time `broadcast` when Reverb/Pusher is configured. Custom channels are registered as `sms`, `whatsapp` and `webpush`. They never throw; a failure is returned and logged. | One message definition reaches every channel, and a failing SMS can't stop other recipients or channels. |
| 85 | **Channel resolution order:** member preferences (church → global → defaults) ∩ the composer's picks, plus channels forced by urgent messages; then digest mode; then the fallback chain; the in-app copy is always included. | Predictable and explainable to members on the preferences page. |
| 86 | **The fallback chain (push → email → SMS → WhatsApp) only applies when none of the member's chosen outside channels can reach them**, and paid channels (SMS/WhatsApp) are used as fallback **only for urgent messages**. | A plain per-channel fallback would text every member without push on every announcement — a real cost to churches. |
| 87 | **Quiet hours** hold push/SMS/WhatsApp until the member's window ends, in their own timezone, using `SendQueuedNotifications` with a delay (fan-out job) or `withDelay()` (direct `notify()`). In-app and email are delivered immediately; urgent messages skip quiet hours. | Nobody's phone buzzes at 2 AM, but nothing is lost. |
| 88 | **Digest mode** keeps routine alerts in-app only. `ff:send-digests` (18:00) emails one summary built from unread rows in `notifications`, so no extra storage is needed. Live and giving alerts are never folded into the digest. | Respects members who want less noise, without hiding time-critical alerts. |
| 89 | **`notification_deliveries` logs every outbound non-in-app delivery** (channel, status, cost, provider ref) through a `NotificationSent` listener. It is pruned after 180 days. | Delivery health, SMS spend per church and composer stats come from one table. |
| 90 | **SMS/WhatsApp run in log mode unless `SMS_ENABLED` / `WHATSAPP_ENABLED` and an API key are set.** The composer shows a cost estimate (members with phones × segments × `SMS_COST_UGX`). | Safe local development, and churches see the cost before they send. |
| 91 | **Notification composer** (`church_broadcasts`): audiences are members, staff, branch, small group or membership stage; send now or schedule (`ff:send-broadcasts` every minute claims rows atomically, so a message is never sent twice). Non-urgent messages respect member preferences; urgent ones force the picked channels. | Covers the spec's targeted church messaging without turning SMS into spam. |
| 92 | **VAPID keys come from `php artisan ff:vapid [--write]`**, which passes the OpenSSL config explicitly. On Windows/XAMPP, web-push encryption also needs `OPENSSL_CONF` set for the PHP process; Linux production needs nothing. | Generating EC keys fails on XAMPP without `openssl.cnf`. |
| 93 | **Analytics are computed live from the source tables** (subscriptions, content_views, attendance, live viewers, prayers, donations, deliveries) over a 30/90/365-day window, with the previous window as the trend baseline. Exports: CSV per dataset, plus a DomPDF summary for church boards. Giving figures need `giving.view`. | No analytics warehouse to keep in sync; at FaithFellows' scale the queries are cheap and always correct. |
| 94 | **Support tickets** (`FF-00001` references): church staff ↔ super admins, with an `open → pending (waiting on church) → resolved/closed` workflow, internal notes the church never sees, assignment, and email + in-app notifications on each reply. | Replaces ad-hoc WhatsApp support with an auditable queue. |
| 95 | **Content reports:** members report posts, comments, prayers, testimonies and live chat. A reported comment is flagged at once. Church moderators work their own queue; super admins see every report plus stale ones (>48 h) and repeat offenders, and can suspend an author. | Churches moderate their own community first, and the platform steps in when needed. |
| 96 | **Platform settings are non-secret key/values** (banner, maintenance note, registrations open, trial length, support contacts). Payment credentials stay in `.env`. The gateways page shows 30-day health per provider and a platform **kill switch** that hides a gateway from giving forms and rejects it in validation. | Staff can react to a provider outage in seconds without touching servers or exposing secrets. |
| 97 | **Suspending a user deletes their sessions**, so the suspension takes effect immediately. `EnsureAccountActive` already blocks suspended accounts. | Otherwise a suspended troll could keep posting until their session expired. |
| 98 | **USSD callbacks check `USSD_SECRET`** (a query string the Africa's Talking callback URL carries) when it is set. | The USSD endpoint is CSRF-exempt and starts payments, so it must not accept forged posts. |

## Sprint 9 — Polish, security & launch

| # | Decision | Why |
|---|----------|-----|
| 99 | **REST API under `/api/v1`** using Sanctum personal access tokens (180-day expiry): auth, directory, follow/unfollow, feed, sermons, events, live, giving (start + poll), prayer wall and notifications. It reuses the same services and policies as the web app, and JSON resources never expose anonymous prayer authors or other members' gifts. | One source of truth for business rules; the mobile app can't drift from the web. |
| 100 | **API hardening:** `throttle:api` (60/min) plus a dedicated login limiter (5 failures per email+IP); suspended accounts lose their token on the next call (`api.active`); **super admins can't mint API tokens**; `/api/*` always renders JSON errors. | Tokens are long-lived and live on phones that get lost. Platform-staff power stays in the browser, with audit and 2FA. |
| 101 | **Security headers on every response** (`nosniff`, `SAMEORIGIN` framing, strict referrer, a Permissions-Policy allowing only geolocation/camera/payment for ourselves, COOP, HSTS on HTTPS in production, `X-Robots-Tag: noindex` on admin and API). **No CSP yet.** | A strict CSP would break church-pasted embeds (YouTube, Facebook, Cloudflare Stream), OpenStreetMap tiles and Stripe. It needs a per-church allow-list first, so it's a post-launch item. |
