# FaithFellows app (Expo / React Native)

Mobile app for FaithFellows. It talks to the Laravel API in `../web` (`/api/v1`, Bearer tokens via Laravel Sanctum).

## Run it

```bash
npm install
cp .env.example .env     # EXPO_PUBLIC_API_URL=auto uses this computer's address; or write http://<your-LAN-IP>:8000/api
npx expo start           # scan the QR code with Expo Go
```

The Laravel server must be running and reachable from the phone (`php artisan serve --host=0.0.0.0 --port=8000` in `../web`).
Sign in with the demo member `member@faithfellows.test` / `password`.

## Structure

```
app/                 Expo Router screens (file = route)
  _layout.jsx          root layout: fonts (Clarity City), splash, auth provider
  index.jsx            entry: tabs, first-run intro or welcome
  onboarding.jsx       four intro slides (illustrations drawn with react-native-svg)
  (auth)/              welcome, login, register, forgot (6-digit code)
  (tabs)/              home feed, churches, sermons, give, profile
  church/[slug]        a church's page      event/[id]      event, RSVP, tickets, QR, questions
  give/[slug]          give (mobile money / card), pledges, repeating gifts
  pay/[reference]      waiting for approval, thank-you      receipt/[reference]   a receipt
  campaign/[id]  campaigns   devotional/[id]  devotionals   announcement/[id]
  sermon/[id]          video / audio sermon      live/[id]     live service with chat
  prayer/              prayer wall, ask for prayer, one request      tickets   my tickets
  legal/[page]         terms and privacy, read in the app
  bible/               reader, passages, and offline.jsx (download the Bible to the phone)
  admin/[slug]/        church staff tools: dashboard, announcements, updates & photos, events (+ door check-in),
                       prayer, members, broadcasts, reports, quizzes, live, giving
  settings/            notifications.jsx (push, email, quiet hours, mute a church)
  post/[id]            an update with all its photos
components/          shared UI (AppText, Button, Pill, StateView, ScreenHeader, CoverHero, PayForm, ListCards…)
  home/                the home screen's sections: banner carousel, church stories, live card, highlights…
lib/                 api.js (Axios + helpers), auth.jsx (session), session.js (secure token), useFetch.js, usePaged.js, payments.js,
                     push.js (push notifications), bibleStore.js / bibleOffline.js / bibleRef.js (offline Bible), upload.js (photos)
constants/theme.js   brand colours, fonts, spacing
assets/              icon, splash, and the welcome pictures (generated by the web app's ContentArtwork)
```

Members never leave the app for something the website can do: every screen above is served by an API endpoint
(see `../web/docs/API.md`). Church staff manage content on the website.

Every screen handles **loading**, **error** and **empty** states through `components/StateView.jsx`.

## Configuration

- `EXPO_PUBLIC_API_URL` — API root ending in `/api` (only `EXPO_PUBLIC_*` variables reach the app). `auto` (or empty, in development) uses the address of the computer running the Expo dev server with port 8000, so the phone keeps working when the Wi-Fi or hotspot changes. Restart Expo with `npx expo start -c` after changing it.
- `EXPO_PUBLIC_APP_ENV` — `development`, `staging` or `production`; picks the URL from `app.json → extra.apiUrl` when `EXPO_PUBLIC_API_URL` is not set.
- `app.json → extra.eas.projectId` — added by `npx eas-cli init` (there is none until you run it).

## Push notifications

The app registers the phone's Expo push token with the server (`POST /api/v1/devices`) after sign-in, and the server
pushes church news, connection requests and chat messages (`../web/docs/API.md`, "Push to the phone"). Members control it
under Me → Notification settings, which also has a "Send me a test" button.

**Who gets a church's news:** only people who follow (are subscribed to) that church, plus its staff. A member who left a
church, follows another church, or muted that church gets nothing from it. A church can also aim a message at a branch, a
small group or a membership stage. The server code is `NotificationService::recipients()`, and a test proves it
(`ApiPushTest`: "church news goes only to the phones of people who follow that church"). No extra package is needed.

To make it work on an Android phone (installed APK, not Expo Go):

1. **Firebase project.** At https://console.firebase.google.com create a project (for example "FaithFellows").
2. **Register the Android app** in it, with the package name `tech.kakebe.faithfellows`, and download **`google-services.json`**.
   Save it as `app/google-services.json` (it may be committed: it holds public identifiers only). `app.config.js` picks it up.
3. **Upload the server key to Expo.** Firebase, Project settings, Service accounts, **Generate new private key**. Then on
   https://expo.dev open the project, Credentials, the Android app `tech.kakebe.faithfellows`, Service credentials,
   **FCM V1 service account key**, upload that JSON. Never commit this file (the root `.gitignore` blocks `*firebase-adminsdk*.json`).
4. **Build a new APK** (`npx.cmd eas-cli build -p android --profile preview`): `google-services.json` goes inside the APK.
5. On the server the queue worker must run (the `queue:work` cron job in `../web/docs/DEPLOYMENT_SHARED_HOSTING.md`); pushes are queued.
6. Check it: sign in, Me, Notification settings, **Send me a test**.

In the web preview and in Expo Go on Android the push code does nothing, and the settings screen says why.

## EAS Update (app changes without a new APK)

Installed APKs download new JavaScript, text and images by themselves when the app opens or comes to the front, then restart into
them (`lib/updates.js`). Me, at the bottom, shows which update a phone runs ("FaithFellows 1.0.0 · update 1a2b3c4d").

**Setting up (once)**

1. Create an access token at https://expo.dev (Account settings, Access tokens, Create token).
2. In GitHub open the repository, Settings, Secrets and variables, Actions, **New repository secret**: name `EXPO_TOKEN`, value the token.
3. Install an APK built after `expo-updates` was added (profiles `preview`, `production-apk`, `production` use the `production`
   channel in `eas.json`). Older APKs cannot receive updates.

**Every day:** change app code, commit, `git push`. `.github/workflows/app-update.yml` publishes it to the `production` channel
in a couple of minutes, and phones take it the next time they open the app. Server changes need nothing from the app.

**What an update cannot carry:** a new native package, a new permission or plugin, an app icon or name change. These live in
the APK. If a push contains one, the workflow stops with an explanation (`.github/scripts/check-native-change.py`): raise
`version` in `app.json` (for example 1.0.0 to 1.1.0), push, and build a new APK. `runtimeVersion` follows `version`, so an
update is only ever offered to APKs of the same version.

**By hand** (needs `eas-cli` and a login): `npx.cmd eas-cli update --channel production --environment production --platform android --message "what changed"`.
The address of the server is stored for that environment on Expo: `npx.cmd eas-cli env:list --environment production`.

## Offline Bible

Chapters you read are kept on the phone automatically; Bible → cloud icon → **Offline Bible** downloads whole books or the
whole Bible per translation (about 4 MB) as one small file per book (`lib/bibleStore.js`, via `expo-file-system`). With no
connection the reader, the Bible tab and passages in reading plans use those copies. To make downloads instant for members,
fill the server's cache once with `php artisan bible:warm kjv` (about 45 minutes).

## Offline notes and highlights

Highlights, and notes you write, pin or delete, are saved on the phone first and sent to the server when there is internet
(`lib/outbox.js`: when the connection returns, when the app opens, every 15 seconds while something waits). The notebook
(`lib/notesStore.js`, `lib/notesSync.js`) and the highlights list open from the phone and refresh in the background. The
signed-in profile is kept on the phone too, so the app starts with no internet. Signing out clears the notes and anything
not yet sent (it warns first); a different member signing in on the same phone clears them as well.

## Gospel radio

A 24-hour station for the whole app (`lib/radio.js`): the super admin adds songs at `/super-admin/radio` on the website and
the app plays them in a loop. On Home there is only a round play button (`components/radio/RadioButton.jsx`), the first tile
in the row of churches, with no picture; it joins the live radio. While it plays, a bar (`RadioMiniPlayer.jsx`) with the
song's picture, name and a stop button stays above the tabs, and at the bottom of every other screen; tapping the bar opens
the full player (`app/radio.jsx`). It keeps playing with the phone locked or the app in the background (iOS and Android
background audio, with lock screen controls). On a real phone this needs a development or store build for Android; in Expo
Go on iPhone background audio works but lock screen controls can be limited.

## Scripture sharing

"Share scripture" (Bible chapter selection bar, passages, devotionals) builds one tidy message with `scriptureMessage()` in
`lib/bible.js`: the verses, the reference with the translation and a short "from FaithFellows" line. It is copied to the
clipboard and the phone's share sheet opens, so the same text pastes into any social app.

## People, near me and chat

`app/people.jsx` has three tabs: **My church**, **Near me** and **Everyone**. Near me asks for your location once
(`lib/location.js`, `expo-location`, approximate only) and lists people by distance bucket ("Within 5 km"). Chat (`app/chat/[id].jsx`)
only works between connected members; you can send one message until the other person replies, and phone numbers, emails and
chat links are refused (the server does the checking, the app shows its message).

## Podcasts

Faith-based podcasts created on the website (`/podcast-studio`) and approved by the super admin. `app/podcasts.jsx` browses,
searches by name, host or topic and filters by category; `app/podcast/[id].jsx` is one podcast (follow, play latest, episodes);
`app/listen.jsx` is the full player (progress bar, back 15 / forward 30, speed, next, "Take notes", Bible and Groups shortcuts).
The player module is `lib/podcastPlayer.js` (one player for the whole app, remembers where you stopped in
`offline/podcasts/progress.json`). It shares `lib/audioFocus.js` with the radio so only one plays; `components/NowPlayingBar.jsx`
shows whichever is on, above the tabs and at the bottom of other screens. Podcasters can import a podcast from its RSS feed on the website (Podbean, Buzzsprout…) and new episodes then appear here by
themselves. Audio is played straight from the link the podcaster
added, so the host must support byte ranges for seeking (all normal audio hosts do).

## Hymn book

`app/hymns/index.jsx` is the hymn book (search by number, title or words, your favourites, hymnals, recently opened),
`app/hymnal/[id].jsx` one hymnal (search and filter by theme, and "Save for offline": `lib/hymnStore.js` keeps the whole
hymnal on the phone), `app/hymn/[id].jsx` one hymn (A- / A+ text size, favourite star, share, auto-scroll, audio when there is
one, the credits) and `app/worship/[id].jsx` worship mode (one verse at a time in large type, light or dark, screen stays on).
Hymns are added by the super admin on the website; every hymn shows who wrote its words and music.

## Home

The Home tab (`app/(tabs)/index.jsx`) is built from sections in `components/home/`: church stories (radio, podcasts, hymns,
churches), notices, `VerseCard` (verse of the day), `QuizCard`, `QuickAccess` (four small shortcuts: prayer wall, sermons,
events, giving), then the feed. Kept short on purpose: each shortcut opens its own screen. All come from the one
`GET /api/v1/home` response.

## Notes

- This is **Expo SDK 57**. APIs change between SDKs, so check the versioned docs (`https://docs.expo.dev/versions/v57.0.0/`)
  before relying on memory. Install native modules with `npx expo install <package>`.
- Audio uses `expo-audio` (`expo-av` no longer exists in this SDK).
- Check dependency health with `npx expo-doctor`; build a JS bundle without a device with `npm run bundle`.
- Accounts: people create an account with email and password in the app (`POST /api/v1/auth/register`) and sign in with
  `POST /api/v1/auth/token`. "Continue with Google" (`lib/google.js`) is built but switched off; set
  `EXPO_PUBLIC_GOOGLE_SIGNIN=1` in `.env` to show it once the Google setup in `../web/docs/API.md` ("Google sign-in
  through the browser") is done.

## Build an Android APK

Builds are made in the cloud by EAS (Expo Application Services), so no Android Studio is needed. You need a free Expo account.

```bash
npx.cmd eas-cli login                          # once
npx.cmd eas-cli init                           # once: creates the project and fills app.json -> extra.eas.projectId
npx.cmd eas-cli build -p android --profile preview
```

The site must be hosted first: see `../web/docs/DEPLOYMENT_SHARED_HOSTING.md`.

The first build asks "Generate a new Android Keystore?": answer yes (EAS keeps the signing key for you). When it finishes
(about 15 to 30 minutes on the free plan) it prints a link and a QR code to download the `.apk`; open it on the phone and
allow "install unknown apps" for the browser.

Profiles in `eas.json`:

| Profile | Gives | Talks to | Use it for |
|---|---|---|---|
| `preview` | `.apk` | the hosted site, `https://faithfellows.com/api` | trying the app on any phone, on any network. This is the one to share with testers. |
| `local-wifi` | `.apk` | the API on your computer over the home Wi-Fi, `http://192.168.0.103:8000/api` (plain http is allowed only in this build, through `ALLOW_CLEARTEXT=1` in `app.config.js`) | developing without Expo Go. The address is fixed in the build: change it in `eas.json` if the computer address changes, and run the API with `--host=0.0.0.0`. |
| `production-apk` | `.apk` | the hosted site | handing the app to people outside the Play Store |
| `production` | `.aab` | the hosted site | uploading to the Google Play Store |

`EXPO_PUBLIC_*` values in `app/.env` are not uploaded (the file is not in git), so the API address of each build is set in
its profile in `eas.json`. Push notifications in an installed app also need a Firebase (FCM) key: see "Push notifications".
