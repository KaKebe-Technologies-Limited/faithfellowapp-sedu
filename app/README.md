# FaithFellows app (Expo / React Native)

Mobile app for FaithFellows. It talks to the Laravel API in `../web` (`/api/v1`, Bearer tokens via Laravel Sanctum).

## Run it

```bash
npm install
cp .env.example .env     # then set EXPO_PUBLIC_API_URL to http://<your-LAN-IP>:8000/api
npx expo start           # scan the QR code with Expo Go
```

The Laravel server must be running and reachable from the phone (`php artisan serve --host=0.0.0.0 --port=8000` in `../web`).
Sign in with the demo member `member@faithfellows.test` / `password`.

## Structure

```
app/                 Expo Router screens (file = route)
  _layout.jsx          root layout: fonts (Clarity City), splash, auth provider
  index.jsx            entry: tabs, first-run intro or welcome
  onboarding.jsx       four intro slides (illustrations drawn with react-native-svg)
  (auth)/              welcome, login, register, forgot (6-digit code)
  (tabs)/              home feed, churches, sermons, give, profile
  church/[slug]        a church's page      event/[id]      event, RSVP, tickets, QR, questions
  give/[slug]          give (mobile money / card), pledges, repeating gifts
  pay/[reference]      waiting for approval, thank-you      receipt/[reference]   a receipt
  campaign/[id]  campaigns   devotional/[id]  devotionals   announcement/[id]
  sermon/[id]          video / audio sermon      live/[id]     live service with chat
  prayer/              prayer wall, ask for prayer, one request      tickets   my tickets
  legal/[page]         terms and privacy, read in the app
  bible/               reader, passages, and offline.jsx (download the Bible to the phone)
  admin/[slug]/        church staff tools: dashboard, announcements, updates & photos, events (+ door check-in),
                       prayer, members, broadcasts, reports, quizzes, live, giving
  settings/            notifications.jsx (push, email, quiet hours, mute a church)
  post/[id]            an update with all its photos
components/          shared UI (AppText, Button, Pill, StateView, ScreenHeader, CoverHero, PayForm, ListCards…)
  home/                the home screen's sections: banner carousel, church stories, live card, highlights…
lib/                 api.js (Axios + helpers), auth.jsx (session), session.js (secure token), useFetch.js, usePaged.js, payments.js,
                     push.js (push notifications), bibleStore.js / bibleOffline.js / bibleRef.js (offline Bible), upload.js (photos)
constants/theme.js   brand colours, fonts, spacing
assets/              icon, splash, and the welcome pictures (generated by the web app's ContentArtwork)
```

Members never leave the app for something the website can do: every screen above is served by an API endpoint
(see `../web/docs/API.md`). Church staff manage content on the website.

Every screen handles **loading**, **error** and **empty** states through `components/StateView.jsx`.

## Configuration

- `EXPO_PUBLIC_API_URL` — API root ending in `/api` (only `EXPO_PUBLIC_*` variables reach the app).
- `EXPO_PUBLIC_APP_ENV` — `development`, `staging` or `production`; picks the URL from `app.json → extra.apiUrl` when `EXPO_PUBLIC_API_URL` is not set.
- `app.json → extra.eas.projectId` — replace `REPLACE_WITH_EAS_PROJECT_ID` after running `npx eas-cli init`.

## Push notifications

The app registers the phone's Expo push token with the server (`POST /api/v1/devices`) after sign-in, and the server
pushes church news, connection requests and chat messages (`../web/docs/API.md`, "Push to the phone"). Members control it
under Me → Notification settings, which also has a "Send me a test" button.

To make it work on a phone:

1. Run `npx eas-cli init` once; it puts your real project id in `app.json → extra.eas.projectId`.
2. Use a **development build** (`npx eas-cli build --profile development`), not Expo Go: Expo Go on Android cannot receive
   remote push any more. iOS needs an Apple developer account for push; Android needs a Firebase (FCM) key added with
   `npx eas-cli credentials`.
3. On the server run a queue worker (`php artisan queue:work`); pushes are queued.

In the web preview and in Expo Go on Android the push code does nothing, and the settings screen says why.

## Offline Bible

Chapters you read are kept on the phone automatically; Bible → cloud icon → **Offline Bible** downloads whole books or the
whole Bible per translation (about 4 MB) as one small file per book (`lib/bibleStore.js`, via `expo-file-system`). With no
connection the reader, the Bible tab and passages in reading plans use those copies. To make downloads instant for members,
fill the server's cache once with `php artisan bible:warm kjv` (about 45 minutes).

## Offline notes and highlights

Highlights, and notes you write, pin or delete, are saved on the phone first and sent to the server when there is internet
(`lib/outbox.js`: when the connection returns, when the app opens, every 15 seconds while something waits). The notebook
(`lib/notesStore.js`, `lib/notesSync.js`) and the highlights list open from the phone and refresh in the background. The
signed-in profile is kept on the phone too, so the app starts with no internet. Signing out clears the notes and anything
not yet sent (it warns first); a different member signing in on the same phone clears them as well.

## Gospel radio

A 24-hour station for the whole app (`lib/radio.js`): the super admin adds songs at `/super-admin/radio` on the website and
the app plays them in a loop. The big round button on Home (`components/radio/RadioHero.jsx`) joins the live radio; a bar
(`RadioMiniPlayer.jsx`) stays above the tabs, and at the bottom of every other screen, while it plays; tapping it opens the
full player (`app/radio.jsx`). It keeps playing with the phone locked or the app in the background (iOS and Android
background audio, with lock screen controls). On a real phone this needs a development or store build for Android; in Expo
Go on iPhone background audio works but lock screen controls can be limited.

## Notes

- This is **Expo SDK 57**. APIs change between SDKs, so check the versioned docs (`https://docs.expo.dev/versions/v57.0.0/`)
  before relying on memory. Install native modules with `npx expo install <package>`.
- Audio uses `expo-audio` (`expo-av` no longer exists in this SDK).
- Check dependency health with `npx expo-doctor`; build a JS bundle without a device with `npm run bundle`.
- Accounts: people create an account with email and password in the app (`POST /api/v1/auth/register`) and sign in with
  `POST /api/v1/auth/token`. "Continue with Google" (`lib/google.js`) is built but switched off; set
  `EXPO_PUBLIC_GOOGLE_SIGNIN=1` in `.env` to show it once the Google setup in `../web/docs/API.md` ("Google sign-in
  through the browser") is done.
